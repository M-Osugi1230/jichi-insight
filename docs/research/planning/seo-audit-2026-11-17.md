## 問題点（重要度つき）

### [中] 1. canonical の欠落が 94/172 ページ
- 福岡県・福岡市・北九州市の深掘りページ、phase9 / phase10 のページ群、都道府県ページ（北海道・宮城・東京・愛知・大阪・広島・香川・沖縄）、policies の initiatives ページ等に canonical が無い。
- 一方で Phase 15 の67市ページと主要セクションページ（トップ、executives、review-progress、corrections、compare 等）には canonical がある。**テンプレートによって実装が不統一**な状態。URL の正規化が効かず、クエリ付き URL 等で重複ページと判定される余地がある。

### [中] 2. 福岡市・北九州市ページの title / description が「当初予算案」のまま
- 例: 福岡市ページの title は「福岡市｜2026年度当初予算案と2024年度決算」、description にも「当初予算案」とある。データ側は PR #640・#641 で成立後の当初予算に更新済みで、**検索結果に表示される文面だけが古い段階のまま**残っている。本文 HTML 内にも「当初予算案」が残存（各2か所）。既知の静的コピー是正フォローと同一件だが、SEO の観点でも優先度が高い（検索結果の第一印象が「案」のままになる）。

### [中] 3. sitemap の lastmod が部分的
- 上記のとおり 69/172 のみ。lastmod はクロールの再訪優先度に使われるため、更新したページ（特に深掘り3自治体と比較ページ）に付いていないのは機会損失。市ページ内の日付の不揃い（4市だけ 2026-10-01）も含め、生成ルールの統一が望ましい。

### [低] 4. 構造化データ（JSON-LD）が全ページに無い
- 全172ページで JSON-LD は0件。必須ではないが、WebSite / Dataset / BreadcrumbList 等を付ければ検索エンジンがサイト構造とデータセット性を理解しやすくなる。任意の改善項目。

### [低] 5. Phase 15 の67市ページすべてに og:image が無い
- 他のテンプレート（トップ、深掘りページ、セクションページ）にはサイト共通の og:image があるが、67市ページには無い。検索順位への影響は限定的で、SNS 等で共有されたときの見栄えの問題。

### [低] 6. 孤立ページが1件
- `/executives/source-requests` は sitemap に収録されているが、他の収録ページからリンクされていない。sitemap 経由でクロールはされるが、内部リンクの評価は付かない。

### [低] 7. 重いページがある
- HTML サイズ: `/municipalities/phase10/fukuoka-projects` 約513KB、`/municipalities/hokkaido` 約285KB、`/review-progress` 約210KB、トップ約134KB。本文は含まれているため致命的ではないが、表示速度とクロール効率の観点では将来の軽量化・分割候補。

### 参考（既知・対応中）
- Search Console で sitemap が「取得できませんでした」と表示される件は既知で週次・月次で観測中。今回の実測でも sitemap 自体は正常配信され、全 URL が 200 を返した。サイト側の問題は確認されなかった。
- /disclaimer・/privacy・/terms は sitemap 未収録（フッターから到達可能）。低重要度。

## 修正提案の振り分け

### Muse 側で PR 可能なもの
1. **sitemap の lastmod 生成ルールの統一と全面付与**（データの最終確認日に基づく生成。トップ・セクション・policies 配下にも付与し、市ページの日付ソースを統一する）。
2. （基盤コードとして可能な範囲で）共通レイアウト側に canonical / og:image の既定値を用意し、テンプレートごとの欠落を底上げする。※見た目は変えないが、レイアウトに触るため GPT 側の UI 作業と競合しないタイミングで行う。

### GPT 側 UI 作業に含めるべきもの
1. **福岡市・北九州市ページの title / description / 静的コピーの「当初予算案」是正**（問題点2。#6 の UI 仕様に既出の必須項目と同一）。
2. **深掘りページ（福岡県・福岡市・北九州市）テンプレートへの canonical と og:image の追加**（問題点1・5の深掘り分）。
3. **/executives から /executives/source-requests への導線追加**（問題点6）。
4. JSON-LD の付与を UI 実装時にあわせて検討（問題点4。WebSite と BreadcrumbList からで十分）。

なお本監査の提案は、計測方針（外部解析 SDK を入れない、PV を目的化しない、人気ランキング的な公表をしない）に沿った技術基盤の整備に限っている。
