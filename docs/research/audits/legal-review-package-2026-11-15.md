## 1. 依頼の目的

Jichi Insight は、自治体・国・議会・監査機関等が公開する一次資料（計画、予算、決算、事業評価、契約、議会資料、選挙公報、監査結果等）を収集・構造化し、「約束（Promise）→ 予算（Money）→ 実行（Action）→ 成果（Result）→ 説明責任（Accountability）」のつながりを住民が自分で確認・判断できる形で公開するプロジェクトです。自治体や政治家を採点・順位付けすることは目的としていません。

正式な Public beta 公開に先立ち、現在の公開方法・公開文書が法的に問題ないかを専門家の目で確認していただくことが本依頼の目的です。プロジェクト内部の整理（本書 §3 の「決定済み事項」）は専門家の確認を経たものではなく、その妥当性の確認も含めてお願いします。

- 公開サイト: https://m-osugi1230.github.io/jichi-insight/ （現在は pre-alpha として公開中）
- リポジトリ: https://github.com/M-Osugi1230/jichi-insight
- 運営体制: 公開責任者である大杉邑大が全ロールを兼務する単独運用（2026-11-15 確定、docs/OPERATIONS_RUNBOOK.md §2）

## 3. 確認してほしい論点

各論点について、「現状」「確認してほしいこと」を記します。資料の所在は §5 の一覧を参照してください。

### 論点1: 原資料の引用・転載の範囲

- 現状: 原資料の全文は転載せず、出典情報（URL・資料名・発行主体・年度・該当ページ）と「短い根拠箇所」の抜粋、および数値等の構造化抽出を公開しています（DATA_POLICY.md の方針、data/ 配下の Evidence 接続）。
- 確認してほしいこと:
  - 「短い根拠箇所」の抜粋が、著作権法上の引用の要件（主従関係・明示等）を満たす運用になっているか。抜粋量や画面表示方法に上限等の条件が必要か。
  - 自治体ごとに利用条件が異なる点（政府標準利用規約に準拠する自治体、CC BY 互換を明示する自治体、独自条件の自治体、条件が不明な自治体）への対応方針として、現行の「提供元規約優先＋不明な場合は全文転載しない」で十分か。条件不明の資料の抜粋掲載をどう扱うべきか。
  - 選挙公報、議会会議録、監査結果、政治資金収支報告書など、資料種別ごとに特別な扱いが必要なものがあるか。

### 論点2: 事実データとデータベースの権利関係、CC BY 4.0 の適用範囲

- 現状: 予算額・KPI・目標値等の事実を構造化したデータについて、プロジェクトの編集成果（構造化・正規化・注釈・Evidence 接続）の範囲に限り CC BY 4.0 を適用すると docs/LICENSING.md に明記しています。
- 確認してほしいこと:
  - 事実の集合に対する編集著作物・データベースの著作物としての扱いと、上記の適用範囲の線引きが表記として十分か。
  - 再利用者が「原資料そのものまで CC BY で許諾された」と誤解しない表記になっているか。誤解防止のために追加すべき文言があるか。
  - 各レコードの出典情報（source_url 等）の保持を再利用者に「推奨」としている現在の表現で足りるか（CC BY 4.0 の帰属表示要件との関係）。

### 論点3: 出典表記の十分性

- 現状: 標準形式「出典: Jichi Insight（原資料: ○○市『○○計画』、参照日）」を docs/LICENSING.md で定め、利用規約 §2 でも独自コンテンツの転載・再配布時に出典と参照日の明示を求めています。
- 確認してほしいこと:
  - CC BY 4.0 が求める帰属表示（著作権者表示、ライセンスへのリンク、変更の明示等）に対して、標準形式と利用規約の定めで不足がないか。
  - サイト内の各画面・データファイル自体に、再利用時に必要となる表示が不足していないか。

### 論点4: 個人情報・要配慮情報・政治資金情報の取扱い

- 現状:
  - 公開対象には、首長・議員等の公人に関する公表情報（氏名、公約、発言、採決記録、議会の海外活動の参加者・費用等。docs/ASSEMBLY_ACCOUNTABILITY.md、docs/PROMISE_EXTRACTION.md）が含まれます。一般住民の個人情報を収集・公開する設計はありません。
  - 訂正・反論申請は GitHub Issue（原則公開）で受け付けており、プライバシーポリシー §3・§5 で個人情報を投稿しないよう求め、誤って投稿された場合の非表示化・編集・削除を「検討する」としています。ただし Git の履歴や外部キャッシュから完全には消去できない旨も明記しています。
  - 政治資金情報については、現時点で収録範囲と取扱い方針を定めた文書がなく、RELEASE_CHECKLIST の確認項目として未完了のまま残っています。要配慮情報（病歴、信条等）を取り扱う設計は現状ありませんが、公約や政党所属など政治的見解に関わる公表情報は扱います。
- 確認してほしいこと:
  - 公表資料に由来する公人の情報を、検索・比較可能な形に再整理して公開することの留意点（個人情報保護法の適用関係を含む。運営者は個人です）。
  - 政治資金収支報告書等の公表資料を今後収録する場合に、扱ってよい範囲と表記の条件。現時点で収録すべきでない情報類型があるか。
  - 要配慮情報に該当しうる公表情報（政治的見解を含む）を扱う際の条件。
  - 訂正申請経由で個人情報が公開 Issue に投稿された場合の対応手順（非表示化・削除の範囲、本人の削除要請への対応）と、プライバシーポリシーの現行文言の十分性。

### 論点5: 利用規約・プライバシーポリシー・免責事項の文面確認

- 現状: /terms、/privacy、/disclaimer の3ページを公開しています（いずれも最終更新日は 2026年7月29日 と表示。ライセンス確定は 2026年11月15日であり、確定後の文言同期はプロジェクト側で別途行いますが、同期後の文面を含め確認をお願いしたい項目です）。
- 確認してほしいこと:
  - 利用規約: 「利用した時点で同意したものとみなす」方式の妥当性、禁止事項の範囲、§2 の再配布条件と docs/LICENSING.md のライセンス条件との整合。
  - プライバシーポリシー: GitHub Pages 等の配信基盤が記録するアクセス情報の取扱い表示の十分性、将来のアクセス解析導入に関する §6 の事前記載の扱い、保存・削除 §5 の表現（「検討します」としている点の適切さ）。
  - 免責事項: 損害への責任を「法令上認められる範囲で負わない」とする条項の有効範囲（運営者の故意・重過失の除外は明記済み）。正確性・完全性を保証しない旨と、プロジェクトが掲げる品質表示（Reviewed 等）との関係で誤解を招く点がないか。
  - 3ページ相互および docs/CORRECTIONS.md（訂正・反論手続）との間に、矛盾する記述がないか。

### 論点6: ライセンス適用範囲の確認（決定済み事項の検証）

- 現状: §2 のとおり 2026-11-15 に決定・実装済みです。
- 確認してほしいこと:
  - 決定内容そのものではなく、(a) 適用開始時点と過去に公開したデータへの遡及の扱い、(b) 外部からの貢献（Pull Request 等）があった場合の権利処理、(c) 「名称はライセンス対象外」とする整理（商標的扱い）の3点について、現在の文書の記載で足りるか。

### 論点7: 自治体名・首長名等の表示と名誉毀損・選挙関連の留意点

- 現状: docs/EDITORIAL_POLICY.md で、人格評価・断定的批判・根拠のない「公約違反」等の表現を避け、見出しには事実・比較条件・対象年度を含める運用としています。免責事項でも「順位や数値だけで優劣を断定するものではありません」と明記しています。
- 確認してほしいこと:
  - 公表資料に基づく事実表示と方法論に基づく「解釈」「評価」表示について、名誉毀損リスクの観点から現在の編集方針と実装で不足する点があるか。特に首長・議員個人に紐づく表示（公約の実行状況、海外活動の費用等）。
  - 選挙期間中を含む表示について、公職選挙法その他で留意すべき点があるか（本サイトは特定候補・政党を推奨しない方針です）。
  - 「評価不能」「確認できませんでした」等の表示が、対象者にとって不利益な誤解を生む可能性と、その回避のための表記条件。

### 論点8: 訂正・反論手続の運用面

- 現状: docs/CORRECTIONS.md に、申請受付（GitHub Issue）、重大度ごとの確認開始目標（P0: 24時間以内／P1: 3営業日以内／P2: 10営業日以内）、審査手順、変更履歴の公開、申請者の立場によって基準を変えない旨を定めています。2026-11-15 に実在の訂正1件を全工程で処理し、変更履歴に correction-2026-001 として公開済みです。
- 確認してほしいこと:
  - 反論掲載・掲載しない判断の記録方法について、紛争予防の観点から追加すべき手順があるか。
  - 第三者が Issue 等へ投稿した内容（第三者の権利を侵害する投稿を含む）に対する運営者の扱いとして、現行の利用規約・プライバシーポリシーの定めで十分か。

## 7. 注意点:「法務確認済み」と表現してよい範囲の線引き

- 外部確認を受けた後にプロジェクトが対外的に言えるのは、**「（確認者の属性・氏名を開示できる場合はその明示のもとで）○年○月○日に、○○の文書・論点について、法務専門家の確認を受けた」という事実とその範囲まで**です。確認を受けていないページ・データ・運用まで含めて「サイト全体が法的に問題ない」「法務確認済み」と包括的に表現しません。
- 確認の対象が文書レビューに限られる場合、データ個別の適法性まで保証されたとは表現しません。
- 確認者が法務の有資格者でない場合は「法務確認」とは呼びません（その場合は §4 の記録にも資格・属性を明記します）。
- 回答で「要修正」とされた項目が未対応の間は、当該項目について確認完了とは記録しません（RELEASE_CHECKLIST の該当項目は、対応完了後にのみ完了とします）。
- 本パッケージ自体は内部準備資料であり、公開ページや対外資料で「法務確認を実施中・完了」と述べる根拠にはなりません。
