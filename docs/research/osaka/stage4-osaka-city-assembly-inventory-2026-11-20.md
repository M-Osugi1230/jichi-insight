## 3. 政務活動費

### 制度（条例で確定）
- 交付は二層：**会派**と**交付対象議員（個人）**。
  - 会派への月額は **57万円または9万5千円のうち会派が選択した額 × 所属議員数**（条例第3条第1項）。
  - **交付対象議員**＝9万5千円を選択した会派の所属議員および無所属議員（条例第2条）。月額 **47万5千円**を個人に交付（同条第3項）。毎月10日交付。
- 収支報告書は会派代表者・経理責任者（個人分は議員本人）が翌年度4月30日までに議長へ提出し、領収書等の写しを添付。提出された報告書・領収書の写しは、提出期限の翌日から90日経過後、**市会ホームページおよび市会図書室で閲覧可能**と制度上は定められている（政務活動費の手引き・令和7年4月改訂、第5章）。
- 根拠：大阪市会政務活動費の交付に関する条例（関係例規集）https://www.city.osaka.lg.jp/shikai/cmsfiles/contents/0000651/651884/kankeisiryou1.pdf ／手引き https://www.city.osaka.lg.jp/shikai/cmsfiles/contents/0000651/651884/01_honbun.pdf ／閲覧要綱（段階0記録）

## 6. 請願・陳情の結果公表

- 制度（市会公式「請願・陳情」ページ https://www.city.osaka.lg.jp/shikai/page/0000002285.html で確定）：
  - **請願**：紹介議員が必要。委員会で審査し、**本会議で結論（採択・不採択）**を出す。
  - **陳情**：紹介不要。**委員会で審査し、委員会で結論（採択・不採択）**を出す（本会議には上程されない）。市外からの郵送等、定められた事項に該当する陳情は委員会に付託されず、標題の一覧表を全議員に周知する扱い。
  - 提出された請願・陳情（提出者の住所・氏名・団体名を含む）は公表すると明記。結論は提出者に文書で通知される。
- **結果公表の形式（確定）**：
  - 議決等案件事項一覧には**請願・陳情の行は載らない**。対象会期（令和8年5・6月）だけでなく、令和7年5月市会・令和8年2・3月市会の一覧でも「請願」「陳情」の記載は0件だった（実物で確認）。※ 令和2年8・9月市会の一覧には請願の行（本会議で一事不再議）があったため、形式上は本会議結論のある請願が載り得るが、近年の会期では実績がない。
  - 陳情の結論は委員会レベルのため一覧には構造的に載らず、審査の経過は**委員会の会議録**（会議録検索システム）に残るのみで、結果の一覧公表は確認できなかった。
  - 対象会期中に請願・陳情の提出・結論があったかどうか自体、一覧からは判別できない（締切日は市会日程に設定されている）。
- 登録設計：対象会期については請願・陳情を**登録対象外**とし、「議決等案件事項一覧に請願・陳情は掲載されず、陳情の結論は委員会審査のため一覧公表がない」ことを sessions の注記と証拠パケットに記録する。請願の本会議結論が出た会期を将来登録する場合は、その会期の一覧の行を正本とする。

- 前例との差異：
  - **名古屋市会との差異**：名古屋は賛否が分かれた1議案のみ議員個人別が公表され、他は会派別を議員別表から集計した。大阪市は議員個人別が全面的に公表なしで、会派別は全案件に一次公表がある（集計が不要）。政活費は名古屋が会派単位のみ・Web 公開1年だったのに対し、大阪市は二層交付で令和3年度分から Web 公表。
  - **札幌市議会との差異**：札幌は賛否が2系統（だより表×議決事件等一覧）の照合を要し、政活費は会派別 PDF のみ（領収書は閲覧申請形式）。大阪市は賛否の一次公表が単一の HTML 一覧で完結し、政活費は領収書まで直接 PDF 公表。ただし札幌にあった「収支報告書の公開期間（5年）」のような削除リスクは大阪市には確認されず、取得の緊急性は低い。
  - **旭川市議会との差異**：旭川は分かれた議案のみ議員別を登録し全会一致分は内訳を作らなかった。大阪市は会派別が全案件に公表されているため、全案件分を公表値どおり登録する。
- 任期：2023-04-30〜2027-04-29（公式2点で裏取り済み、§5）。

## 9. 取得上の注意・API 使用場面

- 大阪市公式サイト（city.osaka.lg.jp）はプログラムからの直接接続（curl）で問題なく取得できた。議決等案件事項一覧は HTML テーブルで機械可読性が高い。
- 政活費の収支報告書 PDF はスキャン画像（テキスト層なし）。金額の登録は総括表（テキスト層あり／XLS 併記）から行う設計のため OCR は不要。
- **API 使用場面：Gemini 等の生成 API は使用しなかった**。一覧 HTML の全行集計、総括表の抽出はプログラム処理と実物の目視確認で完結した。
