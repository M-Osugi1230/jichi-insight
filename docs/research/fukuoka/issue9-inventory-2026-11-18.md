## 3. 3議会の差異のまとめ

1. **表決の粒度**: 県=議案単位の結果文言のみ／福岡市・北九州市=会派別賛否まで公式公表。議員個人別は3議会とも公表なし。「議員別投票の欠損は明示」という受け入れ条件は、3議会すべてで欠損を明示する形で満たすことになる（=欠損は例外ではなく標準状態）。
2. **政務活動費の粒度**: 報告書のオンライン公開は3議会共通だが、議員個人単位まで出るのは福岡市のみ。領収書は3議会とも窓口閲覧のみで、オンラインでは検証できない。
3. **視察の公開**: 福岡市は一覧性が高い（期間・参加者・報告書が1ページに構造化されている）。県は報告書の有無が活動ごとにばらつき、費用は未公表。北九州市は報告書の掲載が平成30年度で止まっている。
4. **議案情報の構造化しやすさ**: 福岡市（表形式・案文リンク付き）と県（番号・件名の一覧）が構造化しやすい。北九州市は賛否一覧がPDF表で、議案番号を持たない種別・件名ベースの表記（賛否一覧表では議案番号欄がない）ため、議案の同定に会議結果側の資料との照合が要る。

## 4. 既存モデルとの接続点と、不足するスキーマ

### 接続点（既にあるもの）

- `proposal.related_project_ids`: 議案→事業（#7 の30事業）への接続が設計済み。予算議案・決算議案は #6 の fiscal_records と fiscal_year＋種別で対応づけられる。
- Phase 15 / #6 の議決情報（fiscal_records の note と証拠パケット）: 3自治体の FY2026 当初予算・FY2024 決算について、議案番号・議決日・結果が一次資料確認済み。Proposal/Vote の初期レコードの出典になる。
- `inspection_trip.policy_follow_up`: 視察→政策反映の接続欄があり、`docs/ASSEMBLY_ACCOUNTABILITY.md` のフォローアップ規則（一次資料がある場合のみ「反映」とする）とセットで使える。
- `evidence_packet` / `source_catalog`: 証拠の仕組みは既存のものをそのまま使える。福岡県議会分はカタログ整備済み。
- #8 の promise との接続: 議員提出議案・附帯決議は首長公約ではなく議会側の行為なので、promise には接続しない（帰属の混同を避ける）。接続先は project / fiscal_record 側が正しい。

### 不足するスキーマ

1. **会派別表決（FactionVote）** — 最重要の不足。福岡市・北九州市の公式データは会派単位であり、現行 `vote.schema.json` では表現できない。選択肢: (a) vote に `faction_votes`（会派名＋賛成/反対/賛否双方あり/欠席＋所属議員数）を追加、(b) 独立スキーマ化。北九州市の「賛否双方あり（△）」のような会派内分裂の表記も受ける必要がある。
2. **議員（Member）** — 現行は assembly 内の会派人数と vote 内の氏名文字列のみ。議員名簿・委員会所属・視察参加者を同一人物として引くには Member レコード（氏名・会派・選挙区・任期・委員会）が要る。ただし議員個人のスコア化に使わない設計（§5）との両立が必要。
3. **政務活動費（PoliticalActivityExpense）** — DATA_MODEL に名前だけある。年度・交付単位（会派/議員）・交付額・支出額・残額（返還）・費目別内訳・報告書の公開状態・領収書の公開範囲（online / in_person_only / not_published）を持つレコードが要る。
4. **附帯決議・修正案の関係表現** — proposal の kind に amendment / resolution はあるが、「どの親議案に付随するか」のリンク（parent_proposal_id 等）がない。修正可決の場合は修正内容の出典も要る。
5. **委員会（Committee）と会期（Session）** — assembly の committees は名前の配列止まり。委員会審査（付託・審査結果）を proposal に結ぶには committee の識別子と、proposal 側の referred_committee が要る。Session は定例会単位のグルーピング（採決結果ページの単位）に必要。
6. **公開指標（DisclosureProfile）** — 議会ごとに「何が・どの粒度で・どこに公開されているか」（本報告書 §2 の表そのもの）をデータ化すると、UI で「この議会は議員別表決を公表していません」と欠損を明示する受け入れ条件を機械的に満たせる。source_catalog の拡張か、assembly レコードへの disclosure セクション追加で足りる。

## 5. 実装の段階案

これまでの Issue と同じ進め方（棚卸し→設計→パイロット→展開→UI仕様引き渡し）を踏襲する。

- **段階0（基盤）**: Assembly レコードを3議会分登録する（定数・会派・委員会・任期、出典は §2.1 の公式ページ）。あわせて DisclosureProfile（§2 の公開状況表）を登録し、欠損の明示をデータで担保する。FactionVote を含むスキーマ拡張（§4-1, 3, 4）を先に決める。
- **段階1（パイロット: 福岡市議会の議案・表決）**: 会議結果ページが表形式で最も構造化しやすく、会派別賛否まで揃う。1定例会分（例: 令和8年第1回、FY2026予算の議案第27号を含む）で Proposal＋Vote（会派別）を登録し、#6 の fiscal_records・#7 の事業との接続を検証する。県議会の海外活動（既存スライス）はこの段階で Assembly レコードと紐づけ直す。
- **段階2（北九州市議会）**: 賛否一覧表PDFからの登録。議案番号がない表記への対応（件名＋種別での同定、会議結果との照合）をパイロットの型に落とす。付帯決議（令和7年12月の第39号の例）を parent リンクの実証ケースにする。
- **段階3（福岡県議会の議案・表決）**: 採決結果ページから Proposal＋Vote（議案単位、member_vote_availability: not_published、会派別も not_published）を登録。3議会で同じモデルが粒度差を吸収できることの証明になる。
- **段階4（政務活動費）**: 3議会の直近年度の収支報告書から、交付単位ごとのレコードを登録。領収書は公開範囲の状態値のみを持ち、内容の検証はしない（できない）ことを明示する。県の政務活動費視察報告書・福岡市の政活費国外出張は inspection_trip との接続候補として扱う。
- **段階5（視察の展開）**: 福岡市の海外視察一覧（構造化済み）→北九州市の報告書（平成30年度まで）→国内の委員会視察は公開状況の確認が取れた議会からの順で。費用は報告書・決算で確認できた場合のみ登録し、なければ cost_status で欠損を明示する。
- **UI**: 各段階でデータ登録後に仕様書を GPT 側へ引き渡す（従来どおり描画は GPT 側）。

## 6. 判断が必要な論点（推奨つき）

1. **議員別投票が公表されていない議会の扱い**
   推奨: 3議会とも議員個人別は公式公表がないので、「議員別は公表されていない」こと自体を DisclosureProfile の一次情報として登録・表示し、推測や会議録からの復元はしない。会派別が公表されている2市は会派別までを登録し、県は議案単位止まりとする。粒度の差を「議会の公開姿勢の差」として見せること自体が本Issueの価値になる。
2. **政務活動費の粒度**
   推奨: 登録単位は公式公開の単位に一致させる（県・北九州市=会派、福岡市=会派＋議員個人）。費目別内訳は収支報告書の様式にある費目までとし、領収書レベルの個別支出は登録しない（オンラインで検証できず、窓口閲覧の転記は再現性・正確性の担保が弱い）。交付額・支出額・残額は報告書の印字値をそのまま使う。
3. **議員（Member）レコードを設けるか**
   推奨: 設けるが、属性は名簿の公開情報（氏名・会派・選挙区・委員会・任期）に限定し、質問回数・発言回数・出席率などの活動量指標は持たせない。受け入れ条件の「質問回数だけのランキングを作らない」をスキーマの時点で構造的に守るため。
4. **視察費用の接続先**
   推奨: 費用は (a) 議会費の決算（款）、(b) 政務活動費の報告書、(c) 視察報告書自体の記載、のいずれかで一次資料が取れた場合のみ金額を登録し、取れなければ状態値で欠損を明示する（既存の県議会3件がこの形）。「費用が取れない視察が多い」こと自体を公開状況として見せる。
5. **対象期間**
   推奨: 議案・表決は現任期の直近1年（FY2026予算・FY2024/FY2025決算が既存データと接続できる範囲）から始め、遡及はしない。政務活動費・視察も直近の公開年度から。網羅性より既存データとの接続（予算→議決→事業→決算の鎖）を優先する。
6. **情報公開・市民参加の指標の定義**
   推奨: 数値指標化は急がず、まず DisclosureProfile（公開の有無と粒度の台帳）として実装する。会議録・中継・傍聴・請願処理の「ある/ない」と公式URLを示すところまでを本Issueの範囲とし、指標の良し悪しの評価はしない（中立性と「採点しない」原則のため）。

| 受け入れ条件 | 現状・見通し |
|---|---|
| 3議会が1モデルを共有 | 既存4スキーマが土台になる。会派別表決と政務活動費のスキーマ追加が前提 |
