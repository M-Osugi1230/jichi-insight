# Issue #7 描画 UI 仕様（GPT 側引き渡し用）— 2026-11-17

対象: 重点事業ページ（予算→成果ライフサイクル）。データ側は PR #642〜#647 で登録完了（3自治体×10事業＝30事業が Reviewed）。本仕様は描画のみを扱う。

## 使えるデータ
データ層: 各自治体の lib アクセサ（`apps/web/lib/kitakyushuProjects.ts` / `fukuokaPrefectureProjects.ts` / `fukuokaCityProjects.ts`）。
- 事業系列（series_id）＋年度別 project レコード: 目的・対象（target_population、未登録の場合は null）、担当課、上位施策（parent_policy、未登録は null）、公式評価（official_evaluation）、段階別の金額（当初予算／決算／翌年度額など、段階はレコードに明示）。
- KPI 独立レコード: baseline / target / actuals の分離、assessment（achieved / mostly_achieved / in_progress / not_assessable / not_published / not_applicable）、causality_note（全件あり）。
- 証拠パケット: 出典・確認範囲・open_questions（未取得項目の明示）。
- 選定カタログ: 選定ルールとスキップ記録（「なぜこの30事業か」を説明する材料）。

## UI タスク
1. **事業ページの新設**: 自治体ページから辿れる事業一覧＋事業詳細。詳細はライフサイクルの時系列表示（計画・公約接続は未登録のため「未接続」と明示 → 当初予算 → 決算 → KPI 実績 → 公式評価・翌年度の方向性）。廃止・終了事業（北九州市「外国人との共生社会推進事業」＝後継事業へ再編、福岡県「男性の育児休業取得促進事業」＝終了（完了））は終端として表示する。
2. **KPI 表示**: 基準値・目標・実績を混同しないレイアウト。assessment の状態語彙は既存の `lib/statusLabels.ts` に合わせる。causality_note（因果関係の限界）を KPI の近くに常時表示する。
3. **段階ラベルの厳密表示（必須）**:
   - 北九州市の決算額は「令和7年8月公表時点・議会認定前」の値。認定済みの決算と誤認される表示にしない。
   - 福岡県の令和8年度事業費は「予算案の額」。成立した当初予算と並べて同格に表示しない。
   - 福岡市の当初予算額は全件「当初予算案」段階の額（市の説明資料が公式サイトから削除済みで成立額の事業別内訳が取得できないため）。決算額は未登録 — セクション自体を「未取得」と明示し、空欄や推測値で埋めない。
4. **欠損の明示**: target_population / parent_policy が null の事業、KPI が空の事業（福岡市「ポートセールス事業」）、数値非公表の指標（同「ウォーターフロント再整備の推進」）は、欠損として見える形にする。
5. **選定方法の説明**: 事業一覧の冒頭に、公式母集団と選定ルール（柱ごとに掲載順、金額順ではない）の要約と、選定カタログへの参照を置く。

## 守るべき線引き（受け入れ条件由来）
- 評価は自治体の公式評価のみを表示し、サイト独自の採点・順位付けはしない。
- KPI の目標と実績を同じ系列・同じ色で混ぜない。因果の限界表示を省略しない。
- 契約・議会・監査は全事業で未登録（公式対応表がないため）。セクションを作る場合は「未収録」と明示する（項目自体を無いことにもしない）。
- 首長公約との接続は Issue #8 のレジストリ登録後に行う。それまでは「未接続」と表示する。

## 完了の定義（Issue #7 受け入れ条件）
- 30事業が Reviewed（データ側で達成済み）／全事業に出典パケット（達成済み）／段階と年度の明示／KPI 目標と実績の非混同／因果の限界表示／3自治体種別で再利用できる事業ページ — 描画側は最後の3点が主対象。
