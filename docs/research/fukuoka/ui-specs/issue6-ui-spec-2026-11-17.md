# Issue #6 描画 UI 仕様（GPT 側引き渡し用）— 2026-11-17

対象: 福岡県・福岡市・北九州市の自治体ページ。データ側は PR #639（県）・#640（福岡市）・#641（北九州市）で登録完了。本仕様は描画のみを扱う。

## 使えるデータ（すべて reviewed、出典・証拠パケット付き）
データ層: `apps/web/lib/finance.ts` の汎用アクセサ `settlementSeries(metric)` / `breakdownItems` / `breakdownChildren`、および各自治体の lib（`fukuokaCityFinance.ts` 等、決算系列は settlement_records.json をマージ済み）。

3自治体とも決算 FY2022–FY2024・**普通会計**で次の系列が揃っている:
- 歳入総額・税収・歳出総額・形式収支・繰越財源・実質収支・実質収支比率・標準財政規模
- 目的別歳出（県22区分／両市13区分、breakdown 配列）
- 性質別歳出（breakdown 配列、parent_key による階層つき。「うち」内数は二重計上しない構造）
- 基金残高（総務省3区分）・地方債残高
- 経常収支比率・実質公債費比率・将来負担比率・財政力指数
- 住基人口（年度ごとに基準日が異なる。レコードの note に明記あり）

加えて両市は FY2026 一般会計当初予算（**成立後**）の歳入・歳出・税収が千円精度で登録済み。一般会計の FY2024 決算系列も従来どおり別系列で存在する。

## UI タスク
1. **SettlementTrend の汎用化**: 現在は福岡県データ直結の専用実装。3自治体の決算系列（普通会計）に使える汎用コンポーネントにする。
2. **新規セクション**: 目的別・性質別の内訳、基金・地方債、財政指標、住民1人あたり値（人口レコードから算出する場合は算出であることを明示し、人口の基準日も併記）。
3. **静的コピーの是正（必須）**: `apps/web/app/municipalities/fukuoka-city/page.tsx` と `kitakyushu-city/page.tsx` のタイトル・説明文・本文に残る「当初予算案」表記を、成立後の当初予算に改める（データ側は是正済みで、現状はページ表記だけが古い）。
4. **プロフィールの平易な説明文**: データ未収録。自治体公式プロフィールに基づき出典を明示して作成すること（推測で書かない）。

## 守るべき線引き（受け入れ条件由来）
- 各セクションにデータ年度・出典・鮮度を表示する。
- 当初・補正後・決算の数値を混ぜない。普通会計と一般会計の系列も混ぜない（系列ごとにラベル明示）。
- 欠損は明示する。例: 北九州市 FY2023 の経常収支比率（臨財債等除く）は未収録 — 補間せず「未収録」と表示する。福岡県の県独自の性質別区分（expenditure_by_nature_prefecture）は標準区分と合算・混用しない。
- 比較は併記まで。ランキング形式にしない。
- 住民1人あたり値は参考値として、算出根拠（人口の出典・基準日）を併記する。
