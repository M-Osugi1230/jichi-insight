# Jichi Insight 効果測定フレームワーク

採用日： 2026-11-15（正式公開と同日）。本書は、公開後の改善サイクルで使う物差しの正本です。運用手順は docs/OPERATIONS_RUNBOOK.md、訂正の目標は docs/CORRECTIONS.md、最上位の目的は docs/NORTH_STAR.md を参照します。

## 1. 目的

最上位の目的は「住民が、自分自身で自治体、知事・市長、議会を評価できる情報環境をつくる」ことです。アクセス数そのものは目的ではありません。本フレームワークは、その目的に近づいているかを次の4つの問いで測ります。

| # | 問い | 意味 |
|---|---|---|
| Q1 | 見つけられるか | 評価したい自治体の情報に、検索等から到達できるか |
| Q2 | 理解できるか | 一次資料の原文を読まなくても、約束→予算→実行→成果のつながりが分かるか |
| Q3 | 信じられるか | 出典・品質状態・未確認範囲が伝わり、誤りがあれば正されるか |
| Q4 | 判断に使われたか | 実際の評価・議論・報道・議会質問等で参照された形跡があるか |

## 2. 指標とデータソース

測れる手段があるものだけを指標にします。手段がない指標は、推測で語らず「測っていない」と記録します。

### Q1 見つけられるか

- データソース： Google Search Console（対象プロパティ： `https://m-osugi1230.github.io/jichi-insight/` の URL プレフィックス プロパティ、2026-11-15 作成）。
- 指標： 表示回数、クリック数、主要クエリ（自治体名＋予算／決算／総合計画 等）、sitemap 対象ページのインデックス登録状況。
- GitHub Pages でも Search Console は利用可能です。計測はここから始まります。

### Q2 理解できるか

- データソース： 3分理解テスト（公開前の実施キットを公開後も継続使用し、結果を時系列で比較）。
- セッションの導線到達率（ホーム→自治体ページ→個別の接続表示）は**測りません**。現行ホスティング（GitHub Pages）は標準のアクセス解析を持たず、外部解析 SDK の導入はプライバシー方針との整合確認が前提となるため、現在の構成では採用しません。理解の度合いは理解テスト等の定性手段で代替します。

### Q3 信じられるか

- 訂正申請の件数と、確認開始までの時間が docs/CORRECTIONS.md の目標内か（P0： 24時間以内、P1： 3営業日以内、P2： 10営業日以内に確認開始）。OPERATIONS_RUNBOOK §11 の週次計測と連動します。
- 変更履歴の公開遅延（修正のマージから変更履歴への掲載までの日数）。
- 鮮度： 収録データの最終確認日からの経過と、確認作業の実施記録。

### Q4 判断に使われたか

- 外部からの参照： 報道・ブログ・議会資料・自治体自身の資料からの引用・リンクを、検索と手作業の記録で定性的に把握します。
- 訂正・反論・問い合わせの内容分析： 住民がどの自治体のどの接続を見て疑問を持ったかは、情報環境が使われている証跡として記録します。
- 再訪・継続利用は、解析手段がない現行構成では測れません。測れないことを明記し、推測で語りません。

## 3. 測らないこと（設計上の線引き）

- 自治体同士の「人気ランキング」は公表しません。プロジェクトの中立性原則と矛盾するため、内部把握用の集計も公表対象にしません。
- 個人を追跡する計測（フィンガープリント等）は導入しません。解析ツールを導入する場合は、プライバシーポリシーの改定と法務確認を先に行います。
- 数値目標（PV 等）を目的化しません。指標は Q1〜Q4 の問いに答えるための材料としてのみ使います。
- Q2 のセッションファネルは、現在のホスティング／プライバシー方針のもとでは測りません（§2 Q2 参照）。

## 4. 計測の周期と記録先

- 正式公開後4週間（2026-11-15〜2026-12-13）は、OPERATIONS_RUNBOOK §11 の安定運用計測と一体で**週次**確認し、本書の Q1・Q3 指標を併記します。
- その後は**月次**で Q1・Q3・Q4 を記録し、**四半期ごと**に Q2（3分理解テスト）を実施します。
- 記録先は公開判断の記録である Issue #12 とします。計測結果の公表範囲は所有者が別途判断します（§6）。
