## 0. 結論

**大きく作り直す前に「問い → 地域 → 現在の根拠／未収録」をつなぐ入口を、地図と並列で最初に出す**ことを推奨する。

現行実装には自治体検索、財政比較、3議会の議案／会派表決、3首長の公約、3自治体の事業と公式根拠がある。一方、ホームの冒頭は日本地図 `JapanMapExplorer` が主役で、「知りたいことから、調べる」のタスクカードは後段の折りたたみ `<details className={styles.mapDeepDive}>` 内にある（`apps/web/app/page.tsx`）。主要ナビも資料種別の分類が中心で、利用者が「借金」「子育てへの支出」「誰が賛成した」から入る際の翻訳負荷が残る。

**これは静的コード監査に基づく仮説。** 2026-11-19 時点で `https://jimieru.com/` 等の本番ページ取得を試みたが外部取得環境から本文を確認できなかったため、ブラウザ上の実際の挙動・見た目や利用者の迷いを「確認済み」とは記載しない。詳細は参考調査 §0。以下の経路は **コード上で確認できたリンク・ルート**を基に記したもので、実機のクリック実証は未実施。

### 現行の強み — 変更しないもの

- ファーストビューの地図・自治体名からの検索は既存ユーザーの入口として維持する。**問いの入口を追加し、地図を削除しない**。
- 政策・財政・実績・議会・公約を分離し、原資料と接続を Reviewed として示す考え方。
- `/compare` の比較条件のゲート。異条件の数値を同じ表に入れない。
- 議会の公開制約、未収録や `not_assessable` の定義。ランキングや首長・議員スコアを設けない。
- `docs/MEASUREMENT.md` の Q1〜Q4。外部解析 SDK・個人追跡なし。

## 2. 推奨情報設計（変更後の想定）

```text
ホーム
 ├─ 知りたいことから探す（地図と並列の可視入口）
 │   ├─ 市の借金・基金・財政健全性を調べる
 │   ├─ 首長の公約と根拠を確認する
 │   ├─ 議案と公表された賛否を見る
 │   ├─ 子育て／道路／観光など事業の予算・結果を確認する
 │   └─ 条件が揃う数値を2市で並べる
 └─ 地域から探す（現行地図・自治体名検索を維持）
      ├─ 自治体を選択
      └─ その自治体の「確認できること」メニュー
           ├─ この自治体の財政 → 利用可能な指標／未収録の説明
           ├─ 公約 → 対象が3首長に含まれる場合のみ現行レジストリ
           ├─ 議会 → 3議会の公開範囲（個人賛否は非公開）
           ├─ 重点事業 → 登録済み対象のみ
           └─ 公式出典・確認範囲
```

**重要**: 自治体を選んでも、その自治体のすべての情報があるとは示さない。「登録された情報」「対象外」「未収録」「公表されていません」を明確に区別する。「対象外」は Jichi Insight の対象範囲外、「公表されていません」は公式公開状態を確かめた場合に限定する。

## 4. 低忠実度ワイヤーフレーム（提案のみ）

### 4.1 ホーム上部

```text
┌────────────────────────────────────────────────────┐
│ Jichi Insight   自治体を、自分で確かめる。           │
│                                                    │
│ 何を知りたいですか？                                │
│ [借金・財政を知る] [公約を確かめる]                 │
│ [議会で何が決まった？] [事業のお金と結果は？]       │
│ [同じ条件の数値を並べて見る]                       │
│                                                    │
│ 地域から探す                                        │
│ [自治体名を入力する _______________________]         │
│ [従来の日本地図：47都道府県＋Reviewed対象市]       │
└────────────────────────────────────────────────────┘
```

- 地図を取り去らず、同じトップの可視領域に問いと地図の二つの入口を置く。画面幅が狭いときも、ボタンとしての役割と順序が分かる形にする。
- カードに数字・達成率・順位を表示しない。「何が調べられるか」を直接説明する。
- 地域選択を義務化しない。一般説明に先に進める経路を残す。

### 4.2 「借金・財政を知る」の着地（例）

```text
この市の財政について
[確認できるもの]  2024年度の一般会計決算（出典）
[未収録]          市債残高（本サイトの reviewed 値）
[未収録]          将来負担比率（本サイトの reviewed 値）
※未収録は、市が資料を公表していないという意味ではありません。
[公式資料を見る] [予算と決算の違い] [市ページへ]
```

**上記は表示案であり、特定市の FY2024 値や収録状況を確認したという意味ではない。** 採用する場合は対象市の実データから正しい年度と状態を選ぶこと。

### 4.3 「議会で何が決まった？」の着地（例）

```text
[福岡市議会] [令和8年第1回定例会 ▾]
議案番号・件名で探す [________________]
収録議案: 126件 （絞込中: 12件）   [絞込を解除]
● 議員ごとの賛否は公表されていません。
● この議会では会派別の賛否を確認できます。
[議案番号 | 原文件名 | 議決日 | 結果の登録表記 | 会派別賛否 | 出典]
```

福岡県議会では **「会派ごとの賛否は公表されていません」** を表示し、会派表決の空欄を見せない。結果原文がデータにない議案は原文を作り上げない。

## 5. 評価計画 — 新しい追跡 SDK を使わない

既存 `docs/MEASUREMENT.md` の **Q1: 見つけられるか、Q2: 理解できるか、Q3: 信じられるか、Q4: 判断に使われたか** に接続する。PV や滞在時間は目標にしない。

### タスクテスト（現状→提案モック→実装後、各回で同じシナリオ）

| シナリオ | 成功条件（正しい判断を含む） | 記録するもの |
|---|---|---|
| A: 「盛岡市の借金について調べたい」 | 市の財政ページへの導線を発見し、借金指標のデータが本サイトで**収録されているか**を正しく回答。ない場合は「未収録」を認識できる。 | たどったページ、戻り・迷い、最終的な認識 |
| B: 「福岡市長の公約の進捗を確認したい」 | 原文公約と評価材料の有無を区別し、「資料がない＝未達」を避ける。 | 到達先、誤認の有無 |
| C: 「北九州市の予算議案に誰が賛成？」 | 会派別の公表状態に到達し、議員別は未公表と理解する。 | 検索・絞込の利用、公開単位の理解 |
| D: 「観光の事業費と成果が知りたい」 | 対象3自治体の登録事業を探し、予算／決算／公式 KPI の区分と未接続を説明できる。 | 検索語と結果理解 |
| E: 「福岡市と北九州市を比べたい」 | 同条件4指標の比較に到達し、比較の限界を言える。 | 比較できた項目、比較できない項目 |

- **対象者**: 事前知識の違う住民を含む小規模な定性検証。実人数・合格基準は所有者が別途決定する。ここで仮の達成率を作らない。
- **環境**: スマートフォン、デスクトップ、キーボードだけ、VoiceOver 等のスクリーンリーダーで実施。リンク名、見出し、スキップ導線、絞込解除が分かること。
- **記録**: 本人がどこに行けばよいと思ったか、どの言葉が分からなかったか、欠損をどう解釈したかを匿名の自由記述で残す。個人別クリック追跡はしない。
- **確認**: Search Console の公開検索クエリ傾向（既存フレームの Q1）と、3分理解テスト（Q2）、一次資料への信頼・訂正対応（Q3）を補助材料にする。検索露出数が増えてもそれ自体を成功としない。

### 提案の受け入れ条件（実装 Issue に転記する候補）

1. ユーザーがホームから **「問い」または「地域」** のどちらでも調べ始められる。地図が引き続き存在する。
2. 5つの問いの先で **「回答可能な範囲／未収録・未公表」** を早期に確認できる。存在しない公的記録を生成しない。
3. 3議会の議員別賛否は全て未公表と明記し、県の会派別も未公表。会派別情報は両市だけ。質問回数・賛否・支出のランキングを作らない。
4. 比較は **同年度・同会計・同段階・同指標定義・単位・レビュー状態の一致**を確認し、条件不一致は表に入れない。
5. 全レコードの出典・確認日・状態文言を保持し、絞込中も全件解除／元データへの経路がある。
6. キーボード・スクリーンリーダーで問い・検索結果・詳細出典をたどれる。情報は視覚表現だけで伝えない。
7. 外部解析 SDK、個人追跡、PV を目的とした最適化、首長・議員・議会・自治体の政治的採点や人気順位は **一切追加しない**。
