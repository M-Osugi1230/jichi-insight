# 検証・判定基準（クラスター展開の運用正本）

制定: 2026-11-23（所有者指示により、Notion フィールドガイド「A new shape for work」の
考え方を本プロジェクトの実運用として明文化したもの）

本書は、自治体クラスターの展開作業（段階0〜4＋Web 仕上げ）で実際に使ってきた
検証・判定の基準を、作業の前に参照できる形で明文化した正本である。
新しい段階・新しいクラスターを開始する前に、本書の該当節を確認すること。
基準自体を変更する場合は、本書を PR で更新し、変更理由を PR 本文に記録する。

## 運用原則

1. **基準は作業前に明文化する**: 各段階の着手前に、本書の該当節と対象 Issue の
   方針が食い違っていないか確認する。食い違いがあれば、作業を始める前に
   Issue 側か本書側かを所有者委任の範囲で判断し、判断を記録する。
2. **記録の正本は repo と共有ドキュメント**: 判断と検証結果は、Issue コメント・
   PR 本文・証拠パケット・docs/ に記録する。チャットの会話だけに残して
   終わらせない。申し送り事項は Issue #706 に集約する。
3. **古くなった記述はその場で直す（context rot 対策）**: 件数・状態・手順の
   記述が実態とずれているのを見つけたら、発見した作業の範囲で即時に直す。
   直せないものは #706 か該当 Issue に申し送りとして記録する。

## 共通原則（全段階）

- 一次資料（公式ページ・公式 PDF・公報・選管資料）のみを根拠にする。
  Wikipedia・報道・二次資料の値は使わない（誤りの実例が多数ある）。
- 不明な値は推測や 0 で補完しない。未公表は null ＋理由明記で登録する。
  ただし原典に「0.0」と印字されている値は公表値として収録する。
- 候補・下書き（prepared / scaffold）と Reviewed を混同しない。
  人間レビューや公開承認を偽装しない。
- main へ直接コミットしない。ブランチ＋PR を経由し、CI 全緑を確認してから
  マージする。マージ後は本番の deployed_commit_sha が main と一致し、
  status が verified であることを確認してから完了を記録する。
- 棚卸し（段階0）の記録は設計の土台であり、登録値そのものではない。
  登録値は常に対象資料の実物で再検証する。

## 段階1（決算・首長）の基準

- 決算は2系統照合を必須とする: 総務省『市町村（都道府県）決算カード』と
  各自治体公式『財政状況資料集』。全指標×対象3年度で一致を確認する。
  不一致がある場合は、どちらの値を採用したかと理由を証拠パケットに明記する
  （例: 千葉市は印字カード側を採用、熊本県は資料集が総務省データの転載で
  独立性に限界があることを明記）。
- 検算を必須とする: 歳入−歳出＝形式収支、形式収支−繰越財源＝実質収支、
  内訳合計＝歳出総額、基金3区分合計＝基金残高。
- 未公表の指標は value null・value_status "not_published" で理由を明記する。
- 首長の任期は、公式の任期満了一覧の明示値を正とする。明示がない場合は
  前任期満了日の公式公表＋公職選挙法第259条（本文・ただし書）＋
  地方自治法第140条の構成で確定し、構成を証拠パケットに記録する。
  安易な4年加算はしない。欠員選挙は選挙の日から4年（259条本文）、
  出直し選挙は任期の期を変えない。
- 任期開始前の新任期は term として登録しない（証拠パケットに記録し、
  開始後に追加する）。得票数は公式開票結果で確認できる場合のみ記録する。
- 当初予算の千円単位の正確値は、議案本体または補正予算議案の第1表
  「補正前の額」で確認する。概数（百万円単位）で登録しない。
- 議決結果の文言は資料どおりに記録する（「原案可決」「可決」「修正可決」等を
  決めつけない）。

## 段階2（重点事業）の基準

- 登録単位は公式資料の構造と公式評価の公表単位に一致させる
  （例: 新潟市は「政策」ではなく進捗評価が公表されている「10の重点戦略」）。
- 系列の選定は「公式母集団から計画体系の柱ごとに公式資料の掲載順」とし、
  金額順では選ばない。
- 金額・公式評価・KPI は公表されている形でのみ登録する。公表がない項目は
  欠損明示とする。版をまたぐ指標・施策の対応付けは、公式対応表がない限り
  行わない。
- 新規自治体の登録では、municipality_id を段階1の登録値と機械的に
  突き合わせてから PR を作る（広島市の誤記 341003→341002 の教訓）。

## 段階3（公約）の基準

- 原典は選挙公報に限る。原典性の担保は次のいずれかによる:
  (1) 選管の現行公式ページに現存する公報、
  (2) 公式 URL の Wayback Machine 保存コピー（保存元 URL・案内ページの
      明示・ファイルサイズ・候補者一致で担保。複数保存のダイジェスト一致が
      あればなお強い）、
  (3) 保存記録のダイジェストと一致する複写（岡山市長の先例）。
- 候補者欄に「実績」として提示された項目は公約化しない。
- 公報が確保できない場合は公約を作らない。探索記録を
  no_stable_primary_source_found（nonexistence_claim=false＝不存在の
  主張ではない）として証拠付きで登録し、term の manifesto_source_ids は
  空のままにする。二次資料からの公約作成は禁止。
- 事業接続の確信度は low / inferred を上限とする。

## 段階4（議会）の基準

- 賛否表の性質（事後の表決記録か、採決前の態度集約か）は、会議録との
  突合で判定する。突合できない場合は断定せず method=unknown で登録し、
  追認確認を #706 に残す。自治体自身の呼称（「賛否態度」等）も記録する。
- 公表されていない賛否は復元・推測しない。議員別投票が公表されていない
  場合は、そのこと自体を登録する。賛否の公表自体が存在しない議会は
  not_published の欠損明示型とする（福岡県議会モデル）。
- 継続審査中の決算等は pending で登録し、結論公表後に状態を更新する
  （#706 で追跡）。
- 政務活動費の登録単位は公式公開の単位に一致させる。全単位で
  「内訳合計＝支出額」「交付額−支出額＝残額」の検算を行い、原典側の
  不一致は印字どおり登録したうえで差異を記録する。
- 請願は議決対象になる自治体では登録対象に含める。陳情の扱いは
  自治体の制度どおりとする。

## Web 仕上げの基準

- 本文コピーは登録データと突き合わせて検証する。他自治体の流用コピーに
  固有の事実（件数・制度名・計画名・任期）の置換漏れがないか grep で
  確認する。
- 議会数・公約数などの件数ピンは、実測値に合わせて更新する
  （コメントや前回値でなく実データで数える）。
- 新規の財政出典カタログを作ったら、scripts/validate_static_export.py の
  SOURCE_CATALOG_PATHS へ追加する。
- 本番確認は deployed_commit_sha の一致を正とし、対象ページの表示内容を
  実測してから完了を記録する。
